Bab 7: Sistem Login Pengguna, Sandi Argon2id & Hak Akses (RBAC)

7.1 Mengapa Menyimpan Kata Sandi Biasa Adalah Kejahatan Siber?

Bagi orang yang baru pertama kali belajar membuat website, salah satu kesalahan paling fatal yang sering dilakukan adalah menyimpan kata sandi pengguna apa adanya (disebut teks mentah atau plain text) ke dalam basis data. Bayangkan skenario berikut:

⚠️ Bahaya Fatal Menyimpan Sandi Polos
Jika seorang pengguna mendaftar dengan kata sandi Rahasia123! dan Anda menyimpannya begitu saja ke dalam tabel, maka setiap orang yang memiliki akses ke server—atau jika suatu saat server Anda berhasil ditembus oleh peretas—kata sandi tersebut akan langsung terbaca! Parahnya lagi, banyak pengguna menggunakan kata sandi yang sama untuk akun email dan rekening bank mereka.

Untuk mencegah hal tersebut, para ahli kriptografi dunia menciptakan teknik yang disebut Fungsi Hashing Satu Arah (One-Way Hashing).

💡 Analogi Mesin Penggiling Daging vs Kunci Brankas
  • Enkripsi Biasa (Dua Arah) diibaratkan seperti Kunci Gembok. Anda mengunci dokumen penting ke dalam brankas, dan suatu hari Anda bisa membukanya kembali menggunakan anak kunci yang sama.
  • Hashing Satu Arah (Argon2id) diibaratkan seperti Mesin Penggiling Daging. Anda memasukkan potongan daging sapi segar (kata sandi asli), lalu mesin menggilingnya menjadi sosis cincang berlumur bumbu rahasia (string hash acak). Sekali daging itu menjadi sosis cincang, tidak ada ilmuwan atau teknologi manapun di dunia yang bisa mengubah sosis tersebut kembali utuh menjadi sapi hidup!

Lalu bagaimana server tahu bahwa kata sandi yang diketik saat login sudah benar jika server tidak tahu bentuk aslinya? Caranya sangat cerdas: Saat pengguna login dan mengetikkan sandi, server memasukkan sandi ketikan tersebut ke mesin penggiling yang sama. Jika hasil sosis cincangnya identik persis dengan sosis yang tersimpan di lemari data, berarti sandinya pasti benar!

Mengapa WidyaWeb Memilih Argon2id (Bukan MD5 atau SHA-1)?

Algoritma lama seperti MD5 atau SHA-1 sudah tidak boleh digunakan lagi di dunia industri modern. Mengapa? Karena komputer modern dengan kartu grafis (GPU) dapat menebak miliaran kombinasi MD5 per detik (serangan brute-force).

WidyaWeb menggunakan Argon2id, pemenang resmi kompetisi internasional Password Hashing Competition. Argon2id dirancang secara Memory-Hard: algoritma ini sengaja memakan memori RAM komputer saat melakukan penggilingan. Hal ini membuat peretas yang menggunakan superkomputer sekalipun akan kehabisan memori dan bangkrut membayar listrik sebelum berhasil menebak sandi pengguna Anda.

7.2 Mendaftarkan Akun Baru & Memverifikasi Login

Di dalam berkas app/auth.wya, WidyaWeb menyediakan fungsi bawaan untuk menangani pendaftaran anggota baru dan verifikasi login dengan keamanan tingkat tinggi. Perhatikan kode di bawah ini: 

// ==============================================================================
// app/auth.wya - Modul Otentikasi & Keamanan Akun Pengguna
// ==============================================================================
impor "./database.wya";
impor "./logger.wya";

// FUNGSI 1: Mendaftarkan Akun Anggota Baru
fungsi daftarkan_pengguna(email, kata_sandi_mentah, peran) {
    // 1. Pastikan kata sandi memiliki panjang yang cukup aman (minimal 8 karakter)
    jika (panjang(kata_sandi_mentah) < 8) {
        kembalikan {"sukses": salah, "pesan": "Kata sandi minimal harus 8 karakter!"};
    }

    // 2. Giling kata sandi menggunakan Argon2id (menghasilkan string hash acak & aman)
    misal hash_terenkripsi = argon2id_hash(kata_sandi_mentah);

    // 3. Simpan ke tabel pengguna di basis data SQLite
    coba {
        db_jalan("INSERT INTO pengguna (email, hash_sandi, peran, dibuat_pada) VALUES (?, ?, ?, datetime('now'))",
                 [email, hash_terenkripsi, peran]);
        
        log_info("Pengguna baru berhasil didaftarkan: " + email + " (Peran: " + peran + ")");
        kembalikan {"sukses": benar, "pesan": "Akun berhasil dibuat!"};
    } tangkap (galat) {
        log_peringatan("Gagal mendaftarkan akun (mungkin email sudah ada): " + galat);
        kembalikan {"sukses": salah, "pesan": "Email sudah terdaftar, silakan gunakan email lain."};
    }
}

// FUNGSI 2: Memverifikasi Kredensial Saat Pengguna Ingin Masuk (Login)
fungsi otentikasi_masuk(email, kata_sandi_klien) {
    // 1. Cari data pengguna berdasarkan email
    misal user = db_dari("pengguna").dimana("email", email).pertama();

    // Jika email tidak ditemukan sama sekali di lemari data:
    jika (user == nil) {
        log_peringatan("Percobaan login gagal: Email tidak dikenal - " + email);
        kembalikan nil;
    }

    // 2. Masukkan kata sandi ketikan pengguna ke pembanding Argon2id
    misal cocok = argon2id_verifikasi(kata_sandi_klien, user["hash_sandi"]);

    // Jika cocok sempurna:
    jika (cocok) {
        log_info("Pengguna berhasil login: " + email);
        kembalikan user; // Kembalikan data profil pengguna
    }

    // Jika kata sandi salah:
    log_peringatan("Percobaan login gagal: Sandi keliru untuk - " + email);
    kembalikan nil;
}

🔍 Bedah Logika untuk Pemula:

  1. Fungsi argon2id_hash(sandi): Mengambil kata sandi mentah (misal: "kopiTubruk2026") dan secara otomatis menambahkan salt (garam kriptografis acak) lalu mengembalikannya menjadi kode rahasia sepanjang ~90 karakter, misalnya $argon2id$v=19$m=65536,t=3,p=4$dGVzdHNhbHQ.... Di dalam database, yang tersimpan hanyalah deretan kode acak ini.
  2. Fungsi argon2id_verifikasi(mentah, hash): Fungsi ini bertugas membandingkan secara matematis apakah kata sandi mentah yang baru diketik oleh pengunjung menghasilkan struktur hash yang sama dengan yang ada di lemari data. Jika sama, fungsi menghasilkan nilai benar (true); jika salah, menghasilkan salah (false).

7.3 Sesi Pengguna: Bagaimana Server Mengingat Pengunjung?

Protokol HTTP yang menjadi tulang punggung internet memiliki sifat dasar yang unik: Stateless (Pelupa). Artinya, setiap kali peramban meminta halaman baru, server menganggap permintaan tersebut datang dari orang asing yang belum pernah bertemu sebelumnya!

💡 Analogi Gelang Tiket Taman Rekreasi
Bayangkan Anda berkunjung ke Dufan atau Ancol:
  • Saat di gerbang masuk utama, Anda membeli tiket dan menunjukkan KTP (Proses Login).
  • Petugas memasangkan Gelang Kertas Bersegel Barcode di pergelangan tangan Anda (disebut Session Cookie).
  • Sepanjang hari, saat Anda ingin naik wahana Roller Coaster atau Kora-Kora, Anda tidak perlu lagi menunjukkan KTP dan membayar tiket ulang. Anda cukup menunjukkan gelang tiket tersebut kepada petugas wahana (Server).
  • Ketika Anda selesai bermain dan pulang ke rumah, Anda menggunting gelang tersebut (Proses Logout).

Di dalam WidyaWeb, gelang tiket ini dikirimkan ke peramban pengunjung sebagai Cookie yang dilindungi dengan 3 tameng pengaman wajib:

🛡️ 3 Tameng Pengaman Cookie Sesi WidyaWeb
  1. HttpOnly = true: Cookie hanya boleh dibaca oleh server web melalui jaringan internet. Kode JavaScript peramban tidak diizinkan menyentuhnya sama sekali. Ini membuat hacker tidak bisa mencuri sesi Anda meskipun mereka mencoba menyusupkan skrip jahat (kebal XSS).
  2. SameSite = Strict: Cookie hanya akan dikirimkan jika pengguna benar-benar membuka website Anda secara langsung, bukan melalui tautan jebakan dari situs luar (kebal pemalsuan permintaan CSRF).
  3. Secure = true: Pada mode produksi nyata, cookie hanya akan meluncur jika koneksi terenkripsi oleh gembok hijau HTTPS.

7.4 Pembagian Peran dan Wewenang (RBAC: Role-Based Access Control)

Di sebuah kantor atau perusahaan, tidak semua orang memiliki hak yang sama. Seorang kasir hanya boleh mengakses mesin kasir, sedangkan ruang brankas keuangan hanya boleh dibuka oleh manajer atau direktur. Sistem pengaturan hak akses seperti ini disebut Role-Based Access Control (RBAC).

┌────────────────────────────────────────────────────────┐ │ MATRIKS WEWENANG PENGGUNA (RBAC) │ ├──────────────┬──────────────┬─────────────┬────────────┤ │ PERAN (ROLE) │ BUKA PRODUK │ TRANSAKSI │ PANEL ADMIN│ ├──────────────┼──────────────┼─────────────┼────────────┤ │ Pengunjung │ ✅ Boleh │ ❌ Dilarang│ ❌ Dilarang│ │ Kasir │ ✅ Boleh │ ✅ Boleh │ ❌ Dilarang│ │ Administrator│ ✅ Boleh │ ✅ Boleh │ ✅ Boleh │ └──────────────┴──────────────┴─────────────┴────────────┘

Untuk menjaga agar halaman-halaman rahasia tidak bisa diintip sembarangan, kita memasang Middleware Penjaga Gerbang (Guard) pada rute yang bersangkutan: 

// Middleware: Satpam Pintu Khusus Administrator
fungsi satpam_khusus_admin(req, res, lanjut) {
    // 1. Periksa apakah pengunjung sudah login (memiliki sesi aktif)
    misal sesi = req["sesi"];
    jika (sesi == nil atau sesi["pengguna_id"] == nil) {
        // Jika belum login sama sekali, usir dengan kode HTTP 401 Unauthorized
        kembalikan response_json(res, {
            "sukses": salah,
            "pesan": "Akses ditolak: Anda harus login terlebih dahulu!"
        }, 401);
    }

    // 2. Periksa apakah peran di dalam tiket sesi adalah "admin"
    jika (sesi["peran"] != "admin") {
        // Jika dia sudah login tetapi perannya hanya kasir/pengunjung biasa,
        // tolak dengan kode HTTP 403 Forbidden (Terlarang)
        log_peringatan("Akses ilegal terdeteksi oleh user ID " + sesi["pengguna_id"]);
        kembalikan response_json(res, {
            "sukses": salah,
            "pesan": "Akses dilarang: Fitur ini hanya untuk Administrator!"
        }, 403);
    }

    // 3. Jika lolos seluruh pemeriksaan, persilakan lanjut masuk
    kembalikan lanjut(req, res);
}

Bab 8: Validasi Formulir Deklaratif (HTTP 422) & Dokumentasi API Otomatis

8.1 Menghindari "Sampah Masuk, Sampah Keluar" (Garbage In, Garbage Out)

Salah satu prinsip paling kuno namun terpenting dalam dunia pemrograman adalah: Jangan Pernah Percaya pada Data Kiriman Pengguna!

💡 Analogi Petugas Loket Pendaftaran SIM
Bayangkan Anda mendaftar SIM di kantor kepolisian. Di formulir tertulis:
  • Kolom NIK harus berisi tepat 16 digit angka.
  • Kolom Umur harus berupa angka minimal 17 tahun.
Jika ada pemohon yang mengisi kolom NIK dengan tulisan "Kucing Lucu" atau mengisi umur dengan angka minus sepuluh (-10), apakah petugas loket akan meloloskannya ke ruangan ujian praktik mengemudi? Tentu saja tidak! Petugas loket akan langsung mencoret formulir itu dan berkata: "Maaf, formulir Anda belum lengkap dan salah isi. Perbaiki bagian NIK dan umur Anda sekarang."

Di dalam WidyaWeb, petugas loket pemeriksa ini disebut Mesin Validasi Deklaratif. Alih-alih membuat puluhan baris logika jika... maka... yang membingungkan dan rawan terlewat, Anda cukup mendeklarasikan aturan mainnya dalam satu baris sederhana.

8.2 Aturan Validasi Bawaan & Respon Standar HTTP 422

Berikut adalah tabel aturan validasi praktis yang siap Anda gunakan kapan saja:

Aturan Validasi Arti & Batasan Contoh Pemakaian
wajib Data tidak boleh kosong (harus diisi). "nama": "wajib"
email Harus berformat alamat email valid (ada tanda @ dan titik). "email": "wajib|email"
angka Harus berupa bilangan bulat atau desimal. "harga": "wajib|angka"
min:N Nilai angka minimal N atau panjang teks minimal N huruf. "sandi": "wajib|min:8"
max:N Nilai angka maksimal N atau panjang teks maksimal N huruf. "nama": "wajib|max:50"
panjang:N Panjang karakter harus tepat sebanyak N karakter. "nik": "wajib|angka|panjang:16"

Contoh Penerapan Nyata pada Rute Pendaftaran Anggota Koperasi:

// routes/api.wya - Endpoint Pendaftaran Anggota Koperasi Baru
POST(router, "/api/v1/koperasi/daftar", fungsi(req, res) {
    // 1. Tentukan aturan validasi yang wajib ditaati
    misal aturan_skema = {
        "nik": "wajib|angka|panjang:16",
        "nama_lengkap": "wajib|teks|min:3|max:100",
        "email": "wajib|email",
        "simpanan_pokok": "wajib|angka|min:100000"
    };

    // 2. Jalankan mesin pemeriksa terhadap data kiriman pengunjung
    misal data_kiriman = req["badan"];
    misal daftar_galat = validasi_skema(data_kiriman, aturan_skema);

    // 3. Jika ada kolom yang melanggar aturan, tolak dengan HTTP 422
    jika (panjang(daftar_galat) > 0) {
        kembalikan response_json(res, {
            "sukses": salah,
            "pesan": "Formulir pendaftaran tidak valid!",
            "rincian_kesalahan": daftar_galat
        }, 422); // 422: Unprocessable Entity
    }

    // 4. Jika semua data lolos sensor, masukkan ke lemari database
    db_jalan("INSERT INTO anggota (nik, nama, email, saldo) VALUES (?, ?, ?, ?)",
             [data_kiriman["nik"], data_kiriman["nama_lengkap"], data_kiriman["email"], data_kiriman["simpanan_pokok"]]);

    kembalikan response_json(res, {
        "sukses": benar,
        "pesan": "Selamat! Anda resmi terdaftar sebagai anggota koperasi."
    }, 201); // 201: Created (Berhasil Dibuat)
});
🎯 Hasil Respon Saat Terjadi Kesalahan (HTTP 422)
Jika seorang pengguna mencoba mengirim NIK yang hanya 10 angka dan simpanan cuma 20 ribu rupiah, server secara otomatis membalas dengan struktur JSON rapi berikut: 
{
  "sukses": false,
  "pesan": "Formulir pendaftaran tidak valid!",
  "rincian_kesalahan": [
    "Kolom 'nik' harus tepat memiliki panjang 16 karakter.",
    "Nilai kolom 'simpanan_pokok' minimal harus 100000."
  ]
}
Pengembang antarmuka (frontend) di HP atau web dapat langsung menampilkan pesan kesalahan ini di layar pengguna tepat di bawah kotak formulir yang salah!

8.3 Dokumentasi Otomatis OpenAPI 3.0.3 & Portal /docs

Di era lama, setelah membuat API, programmer harus meluangkan waktu berhari-hari menulis buku panduan cara menggunakan API tersebut di berkas Word atau aplikasi Postman. Jika kode diubah, buku panduan sering lupa diperbarui sehingga para pengembang lain kebingungan.

WidyaWeb menyelesaikan masalah ini secara ajaib: Dokumentasi Otomatis!

💡 Analogi Buku Menu Elektronik yang Otomatis Update
Setiap kali Anda menulis GET(router, "/produk", ...) atau POST(router, "/pesan", ...) di kode Widya-Lang Anda, mesin internal WidyaWeb langsung mencatatnya ke dalam spesifikasi standar dunia: OpenAPI 3.0.3.

Cara Menikmati Portal Dokumentasi Interaktif:

  1. Pastikan server WidyaWeb Anda sedang menyala di terminal (widya main.wya).
  2. Buka peramban (Chrome / Edge / Firefox) dan ketik alamat:
    http://127.0.0.1:8080/docs
  3. Layar Anda akan menampilkan antarmuka modern Swagger Portal:
    • Seluruh rute tertera rapi dengan lencana warna-warni (Biru untuk GET, Hijau untuk POST, Jingga untuk PUT, Merah untuk DELETE).
    • Klik salah satu rute, lalu klik tombol "Try It Out".
    • Anda bisa langsung mengisi data uji coba dan menekan tombol Execute untuk melihat respons langsung dari server Anda detik itu juga tanpa perlu menginstal aplikasi tambahan apapun!

Struktur pipa dan kabel disembunyikan di balik dinding (Logika Server), sedangkan yang dinikmati oleh penghuni adalah keindahan lantai marmer, jendela kaca, dan lampu gantung (Tampilan Desain / View).

9.3 Desain Mobile-First (Otomatis Menyesuaikan Layar HP)

Di zaman sekarang, lebih dari 75% pengunjung membuka website melalui smartphone mereka saat di jalan atau santai di sofa. Jika website Anda tampak hancur atau tulisannya terpotong saat dibuka di layar HP kecil, pengunjung akan langsung menutupnya.

Dengan teknik CSS Flexbox & Grid Adaptif yang diterapkan di template WidyaWeb, seluruh tata letak (seperti 3 kolom produk di layar komputer desktop) secara otomatis akan melipat dirinya menjadi 1 kolom vertikal yang rapi saat dibuka di layar ponsel: 

/* Kisi Produk Fleksibel */
.grid-produk {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
  gap: 20px;

Perintah repeat(auto-fit, minmax(280px, 1fr)) di atas bekerja seperti sihir otomatis: jika layar lebar (seperti monitor laptop), peramban akan memasang 3 atau 4 kartu produk berjajar ke samping. Namun begitu dibuka di HP Android atau iPhone berlayar sempit, setiap kartu akan otomatis melebar memenuhi lebar layar tanpa ada tulisan yang terpotong ke kanan!

Bab 10: Komunikasi Real-Time (Server-Sent Events & WebSocket)

10.1 Perbedaan Web Biasa (Klien Bertanya) vs Web Real-Time (Server Menyiarkan)

Mari kita pelajari perbedaan mendasar antara cara kerja web tradisional dan web modern yang serba langsung (Real-Time):

💡 Analogi Menunggu Pengumuman Kereta Api
  • Web Tradisional (Polling Berulang): Anda berdiri di depan loket informasi stasiun dan setiap 5 detik Anda bertanya kepada petugas: "Pak, apakah kereta dari Surabaya sudah datang? Belum. Pak, apakah sudah datang? Belum. Pak, apakah sudah datang?". Tindakan ini membuat Anda capek, petugas stasiun jengkel, dan antrean di loket menjadi macet total.
  • Web Real-Time (Server-Sent Events / Push): Petugas stasiun memasang Pengeras Suara (Loudspeaker) di ruang tunggu. Anda bisa duduk santai membaca koran tanpa perlu mondar-mandir ke loket. Begitu kereta tiba, petugas membunyikan pengeras suara: "Perhatian, kereta dari Surabaya telah tiba di Jalur 3!". Suara itu langsung terdengar oleh Anda detik itu juga!

10.2 Server-Sent Events (SSE): Cara Termudah Mengirim Data Berjalan

Banyak pemula mengira bahwa untuk membuat fitur data langsung (seperti notifikasi pesanan masuk pada layar kasir restoran, grafik beban CPU server, atau lonceng pemberitahuan pesan baru) kita harus membuat sistem yang rumit. Padahal tidak!

WidyaWeb menyediakan teknologi berstandar W3C bernama Server-Sent Events (SSE). Melalui SSE, server menjaga sebuah saluran komunikasi tetap terbuka ke peramban dan bisa mengirimkan data kapan saja: 

// app/sse.wya - Endpoint Aliran Notifikasi Kasir Real-Time
GET(router, "/api/sse/kasir/notifikasi", fungsi(req, res) {
    // 1. Buka pipa aliran SSE ke layar peramban kasir
    misal pipa_aliran = buka_kanal_sse(res);

    // 2. Kirim pesan selamat datang pertama saat terhubung
    pipa_aliran.kirim_event("tersambung", {
        "status": "TERKONEKSI",
        "pesan": "Layar kasir berhasil terhubung ke antena siaran dapur!",
        "waktu": waktu()
    });

    // 3. Pasang telinga pada Bus Peristiwa internal (Event Bus)
    // Setiap kali ada pesanan baru masuk dari meja pelanggan:
    bus_dengarkan("pesanan_baru_masuk", fungsi(data_pesanan) {
        // Siarkan langsung ke layar kasir detik itu juga!
        pipa_aliran.kirim_event("pesanan_masuk", data_pesanan);
    });

    // 4. Tahan koneksi agar tidak ditutup otomatis oleh HTTP biasa
    kembalikan pipa_aliran.tahan_koneksi();
});

Cara Menangkap Siaran Ini di Layar Browser (JavaScript Sederhana):

Di halaman web peramban kasir, Anda hanya perlu menulis 5 baris JavaScript super sederhana ini di dalam berkas HTML: 

<script>
  // Membuka antena penerima sinyal ke server WidyaWeb kita
  const radio = new EventSource('/api/sse/kasir/notifikasi');

  // Menangkap siaran 'pesanan_masuk'
  radio.addEventListener('pesanan_masuk', function(event) {
    const pesanan = JSON.parse(event.data);
    
    // Bunyikan notifikasi lonceng atau munculkan pop-up di layar
    alert("🔔 Pesanan Baru Masuk dari Meja " + pesanan.nomor_meja + ": " + pesanan.nama_menu);
  });
</script>
🎯 Kapan Harus Memilih Antara SSE vs WebSocket?
  • Pilih SSE (Server-Sent Events): Jika Anda hanya butuh pengiriman data dari Server ke Klien (Satu Arah). Sangat cocok untuk: Notifikasi lonceng web, live feed twitter/berita, monitoring kasir, ticker harga emas/kripto, atau log aktivitas sistem. Sangat hemat memori dan otomatis menyambung ulang jika internet ponsel sempat putus!
  • Pilih WebSocket: Jika Anda butuh komunikasi dua arah berkecepatan milidetik tanpa henti. Sangat cocok untuk: Game online tembak-menembak multipemain atau aplikasi video call / live group chat.
