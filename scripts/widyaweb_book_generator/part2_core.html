Bab 3: Program Web Pertama ("Halo Dunia Web") & Siklus Hidup main.wya

3.1 Membedah Berkas main.wya Baris demi Baris

Mari buka berkas main.wya yang baru saja dibuat di proyek Anda. Berkas ini adalah "jantung" aplikasi Anda. Bagi orang awam, melihat kode pemrograman untuk pertama kali mungkin terasa asing, tetapi jika kita bedah satu per satu, logikanya sangat sederhana dan masuk akal: 

// ==============================================================================
// main.wya - Saklar Utama Aplikasi Web Anda
// ==============================================================================

// 1. MENGAMBIL ALAT-ALAT BANTU (IMPOR)
impor "./config.base.wya";        // Mengambil catatan nama website dan nomor port
impor "./app/logger.wya";         // Mengambil alat pencatat aktivitas (CCTV digital)
impor "./app/sanitizer.wya";      // Mengambil alat pembersih teks masukan
impor "./app/database.wya";       // Mengambil alat penghubung ke lemari basis data
impor "./app/web_framework.wya";  // Mengambil mesin web server utama
impor "./routes/api.wya";         // Mengambil daftar alamat rute API kita

// 2. MEMBUAT PROSEDUR UTAMA (FUNGSI UTAMA)
fungsi utama() {
    cetak("==================================================================");
    cetak("🚀 Memulai Server Toko Saya (WidyaWeb Framework)...");
    cetak("==================================================================");

    // A. Membaca pengaturan
    misal cfg = dapatkan_konfigurasi_dasar();
    misal port = cfg["server"]["port"];

    // B. Menyiapkan papan petunjuk arah (Router)
    misal router = buat_router();

    // C. Mendaftarkan Pintu Masuk Halaman Utama (Alamat "/")
    GET(router, "/", fungsi(req, res) {
        // Saat pengunjung membuka alamat utama, beri jawaban sambutan ini:
        kembalikan response_json(res, {
            "status": "AKTIF",
            "pesan": "Selamat datang di website Toko Saya!",
            "pemilik": "Saya Sendiri",
            "waktu_server": waktu()
        }, 200); // 200 artinya: Permintaan berhasil (OK)
    });

    // D. Mendaftarkan rute-rute tambahan dari berkas routes/api.wya
    daftarkan_rute_api(router);

    // E. Membuka pintu gerbang jaringan dan menyalakan server
    jalankan_server(router);
}

// 3. NYALAKAN APLIKASI SEKARANG
utama();

🔍 Penjelasan Rinci Bagian demi Bagian:

  1. Bagian impor: Di awal program, kita memanggil modul-modul yang dibutuhkan. Sama seperti koki yang mengambil pisau, wajan, dan bumbu dapur sebelum mulai memasak.
  2. buat_router(): Router adalah papan penunjuk jalan. Ketika pengunjung datang dan mengetik alamat di browsernya, router bertugas mengarahkan: "Oh, pengunjung ingin melihat Beranda, panggilkan fungsi Beranda! Pengunjung ingin melihat Daftar Produk, panggilkan fungsi Produk!".
  3. GET(router, "/", fungsi(req, res) { ... }): Garis miring "/" melambangkan halaman beranda utama website (pintu depan toko). Variabel req adalah surat permintaan dari pengunjung, dan res adalah amplop jawaban yang akan kita kirim kembali.
  4. jalankan_server(router): Ini adalah saklar pemancar. Perintah inilah yang membuat laptop Anda mulai mendengarkan koneksi jaringan dan melayani pengunjung.

3.3 Troubleshooting: Bagaimana Jika Muncul Pesan Galat?

⚠️ Port 8080 Sudah Terpakai (*Address already in use*)
Gejala: Di terminal muncul pesan "Only one usage of each socket address is normally permitted" atau gagal bind.
Penyebab: Ada aplikasi lain (atau jendela server Widya sebelumnya yang belum dimatikan) yang sedang memakai pintu kamar 8080.
Solusi Mudah: Cukup buka berkas config.base.wya, ubah angka 8080 menjadi 8090 atau 3000, lalu simpan berkas dan nyalakan kembali server Anda. Sekarang website Anda bisa diakses di http://localhost:8090/!

Bab 4: Sistem Routing (Membuat Rute & Pintu Masuk Halaman)

4.1 Apa itu Routing & Metode HTTP?

Ketika kita mengunjungi sebuah website (seperti toko online), kita tidak hanya berada di halaman depan. Kita ingin membuka halaman profil (/profil), halaman daftar barang (/produk), halaman keranjang belanja (/keranjang), atau mengirim formulir pemesanan. Proses pembagian alamat URL ini disebut Routing.

💡 Mengenal 4 Macam Metode HTTP Sehari-hari
Di dunia internet, browser berkomunikasi dengan server menggunakan beberapa "kata kerja" utama:
  • GET (Ambilkan Saya Data): Dipakai saat kita hanya ingin melihat atau membaca informasi tanpa mengubah apapun di server (contoh: membuka halaman berita, melihat katalog barang).
  • POST (Simpan Data Baru Ini): Dipakai saat kita mengirim data baru untuk disimpan ke server (contoh: mendaftar akun baru, mengirim komentar, memesan makanan).
  • PUT (Perbarui Data yang Ada): Dipakai saat kita ingin mengganti atau mengedit data yang sudah ada (contoh: mengganti foto profil, mengedit nomor telepon akun).
  • DELETE (Hapus Data Ini): Dipakai saat kita ingin membuang data (contoh: menghapus item dari keranjang belanja).

4.2 Membuat Berkas Rute Baru (routes/api.wya)

Mari buka berkas routes/api.wya. Di sini kita akan menambahkan beberapa pintu alamat baru untuk toko kita: 

// routes/api.wya - Daftar Rute API Toko Kita
fungsi daftarkan_rute_api(router) {

    // 1. Halaman Informasi Toko (GET /api/v1/tentang)
    GET(router, "/api/v1/tentang", fungsi(req, res) {
        kembalikan response_json(res, {
            "nama_toko": "Warung Berkah Digital",
            "jam_buka": "08:00 - 21:00 WIB",
            "lokasi": "Jakarta, Indonesia"
        }, 200);
    });

    // 2. Rute Dinamis dengan Parameter ID (GET /api/v1/produk/:id)
    GET(router, "/api/v1/produk/:id", fungsi(req, res) {
        // Mengambil nomor ID yang diketik pengunjung di browser
        misal id_barang = req["params"]["id"];

        // Contoh sederhana pengecekan barang
        jika (id_barang == "1") {
            kembalikan response_json(res, {
                "id": 1,
                "nama": "Kopi Robusta Nusantara",
                "harga": 25000,
                "stok": 50
            }, 200);
        } kalau {
            // Jika nomor ID selain 1, beri tahu bahwa barang tidak ada (404)
            kembalikan response_json(res, {
                "sukses": salah,
                "pesan": "Maaf, produk nomor " + id_barang + " belum tersedia"
            }, 404);
        }
    });

    // 3. Rute Menerima Data Kiriman (POST /api/v1/pesan)
    POST(router, "/api/v1/pesan", fungsi(req, res) {
        misal data_masuk = req["badan"]; // Membaca paket data kiriman

        kembalikan response_json(res, {
            "sukses": benar,
            "pesan": "Pesanan Anda berhasil kami terima!",
            "rincian": data_masuk
        }, 201); // 201 artinya: Data berhasil dibuat (Created)
    });
}
🎯 Coba Uji Rute Dinamis Anda di Browser!
Simpan berkas routes/api.wya, nyalakan kembali server Anda, lalu buka browser:
  • Ketik: http://localhost:8080/api/v1/produk/1 ➔ Anda akan melihat data Kopi Robusta!
  • Ketik: http://localhost:8080/api/v1/produk/99 ➔ Anda akan melihat pesan ramah produk belum tersedia dengan kode status 404.

Bab 5: Satpam Pengaman Web (Pipeline Middleware & Keamanan)

5.1 Apa itu Middleware? (Analogi Pos Satpam Perumahan)

Bayangkan Anda tinggal di sebuah perumahan klaster tertutup (*gated community*). Di gerbang utama perumahan ada pos satpam:

PENGUNJUNG DATANG │ ▼ ┌────────────────────────────────────────────────────────┐ │ POS SATPAM UTAMA │ │ (Middleware Before Hook) │ │ 1. Periksa KTP & Identitas Pengunjung │ │ 2. Periksa apakah pengunjung membawa senjata tajam? │ │ 3. Catat plat nomor kendaraan ke buku tamu log │ └───────────────────────┬────────────────────────────────┘ │ Jika Lolos Pemeriksaan ▼ ┌────────────────────────────────────────────────────────┐ │ RUMAH TUJUAN / KAMAR │ │ (Handler Rute Anda) │ │ Menyiapkan hidangan & data yang diminta │ └───────────────────────┬────────────────────────────────┘ │ ▼ ┌────────────────────────────────────────────────────────┐ │ POS SATPAM KELUAR │ │ (Middleware After Hook) │ │ 4. Tempelkan stempel segel keamanan di amplop keluar │ │ 5. Pasang 6 Tameng HTTP Security Headers │ └────────────────────────────────────────────────────────┘ │ ▼ PENGUNJUNG PULANG MEMBAWA JAWABAN AMAN

Di dalam WidyaWeb, Middleware adalah kode yang berjalan otomatis sebelum atau sesudah fungsi halaman web Anda dipanggil. Middleware memastikan bahwa fungsi bisnis Anda (seperti menghitung total belanja) tidak perlu dipusingkan dengan urusan keamanan, karena satpam middleware telah menyaringnya terlebih dahulu di gerbang depan.

5.2 Enam Tameng Keamanan Bawaan (Menjaga Anda Tanpa Pusing)

Setiap jawaban yang keluar dari WidyaWeb otomatis ditempeli 6 tameng pelindung tingkat perbankan:

  1. Tameng Anti-Pembajakan Bingkai (X-Frame-Options: DENY): Mencegah penjahat siber membungkus website Anda di dalam situs palsu untuk menipu klik tombol perbankan (*Clickjacking attack*).
  2. Tameng Anti-Manipulasi Tipe Berkas (X-Content-Type-Options: nosniff): Memaksa browser membaca file teks murni sebagai teks, dan tidak tertipu menjalankan file berbahaya yang menyamar sebagai gambar.
  3. Tameng Kebijakan Keamanan Konten Ketat (Content-Security-Policy): Membatasi agar browser hanya mengeksekusi skrip dari sumber terpercaya, sehingga virus atau injeksi kode jahat (*Cross-Site Scripting / XSS*) otomatis ditolak oleh browser.
  4. Tameng Jalur Aman Terenkripsi (Strict-Transport-Security): Menjamin komunikasi selalu lewat jalur gembok hijau HTTPS yang terenkripsi.

5.3 Membatasi Pengunjung Nakal dengan Rate Limiter

Pernahkah Anda mendengar tentang serangan Brute-Force? Di mana peretas menggunakan robot komputer untuk menebak kata sandi login 1.000 kali dalam satu detik?

WidyaWeb memiliki sistem Rate Limiter Bawaan. Jika ada satu alamat IP komputer yang meminta akses terlalu sering melebihi batas wajar (misal lebih dari 120 kali dalam 1 menit), server WidyaWeb akan langsung memberi kartu merah: 

{
  "sukses": false,
  "galat": "Terlalu banyak permintaan. Silakan coba lagi setelah 60 detik.",
  "kode_galat": "RATE_LIMIT_TERCAPAI"
}

Dengan tameng ini, server Anda tetap tenang, tidak akan kehabisan tenaga, dan terhindar dari kelumpuhan akibat serangan robot botnet (*Denial of Service*).

Bab 6: Menyimpan Data Permanen (Basis Data & Fluent ORM)

6.1 Mengapa Kita Membutuhkan Basis Data?

Jika Anda hanya menyimpan data di dalam variabel program (misal: misal nama = "Budi";), saat server komputer Anda dimatikan atau laptop Anda restart, seluruh data tersebut akan langsung lenyap tak berbekas!

Basis Data (Database) adalah lemari arsip baja yang bertugas menyimpan data secara permanen ke dalam piringan harddisk. Kapanpun komputer dinyalakan kembali, catatan data pelanggan, pesanan, dan transaksi Anda tetap aman tersimpan rapi.

6.2 Membaca Data Semudah Berbahasa Manusia (Fluent ORM db_dari)

Di zaman dulu, untuk membaca data dari tabel, programmer harus mengetik perintah SQL yang kaku seperti SELECT id, nama, harga FROM produk WHERE harga > 10000 ORDER BY id DESC LIMIT 20;. Jika salah satu tanda koma atau spasi saja, program akan langsung error.

Di WidyaWeb, Anda cukup menggunakan Fluent Query Builder db_dari() yang mengalir wajar seperti kalimat bahasa manusia: 

// Contoh Membaca Data Produk dengan db_dari()
misal daftar_produk = db_dari("produk")
    .pilih(["id", "nama", "harga", "stok"])  // Kolom apa saja yang ingin diambil?
    .dimana("kategori", "minuman")            // Hanya ambil yang kategorinya minuman
    .dimana_lebih_dari("harga", 15000)        // Dan yang harganya di atas Rp 15.000
    .urutkan("harga", "DESC")                  // Urutkan dari harga paling mahal
    .paginasi(1, 10);                         // Tampilkan halaman 1 (10 barang per halaman)

6.3 Menambah, Mengubah, dan Menghapus Data (Operasi CRUD)

Mari pelajari 4 operasi paling penting dalam pengelolaan data: 

// 1. MENAMBAH DATA BARU (CREATE)
db_jalan("INSERT INTO produk (nama, harga, stok) VALUES (?, ?, ?)",
         ["Teh Melati Segar", 12000, 100]);

// 2. MEMBACA SATU DATA SPESIFIK (READ)
misal barang = db_dari("produk").dimana("id", 1).pertama();
cetak("Nama Barang: " + barang["nama"]);

// 3. MENGUBAH / MEMPERBARUI DATA (UPDATE)
db_jalan("UPDATE produk SET stok = ? WHERE id = ?", [85, 1]);

// 4. MENGHAPUS DATA (DELETE)
db_jalan("DELETE FROM produk WHERE id = ?", [99]);

6.4 Transaksi Atomik: Menjamin Uang Tidak Hilang di Tengah Jalan!

Bayangkan Anda sedang mentransfer uang sebesar Rp 100.000 dari rekening Andi ke rekening Budi. Ada 2 langkah yang harus terjadi:
1. Saldo Andi dipotong Rp 100.000.
2. Saldo Budi ditambah Rp 100.000.

Bagaimana jika tepat setelah saldo Andi dipotong, tiba-tiba listrik padam atau koneksi server terputus sebelum saldo Budi bertambah? Uang Rp 100.000 itu akan raib di antah berantah!

WidyaWeb menyelesaikan masalah ini dengan Transaksi Atomik ACID (db_transaksi): 

// Transaksi Keuangan Aman Terpadu
misal sukses = db_transaksi(fungsi(tx) {
    // Langkah 1: Kurangi uang Andi
    tx.eksekusi("UPDATE dompet SET saldo = saldo - 100000 WHERE nama = 'Andi'", []);

    // Langkah 2: Tambahkan uang Budi
    tx.eksekusi("UPDATE dompet SET saldo = saldo + 100000 WHERE nama = 'Budi'", []);

    kembalikan benar;
});
// Jika salah satu langkah gagal, seluruh perubahan otomatis DIBATALKAN (Rollback)
// seolah-olah tidak pernah terjadi apa-apa. Saldo Andi tetap utuh 100%!
