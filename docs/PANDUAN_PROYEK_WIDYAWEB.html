Bab 1: Mengenal Dunia Web & Filosofi WidyaWeb

1.1 Apa Sebenarnya yang Terjadi Saat Kita Membuka Website?

Sebelum kita mulai menulis kode, mari pahami terlebih dahulu cara kerja website. Bayangkan Anda sedang pergi ke sebuah Restoran:

💡 Analogi Restoran: Klien, Pelayan, dan Dapur
  • Browser Anda (Google Chrome / Edge) adalah Pelanggan yang duduk di meja makan.
  • Alamat Website (misal: http://localhost:8080/menu) adalah Daftar Pesanan yang ingin Anda minta.
  • Jaringan Internet & Protokol HTTP adalah Pelayan yang mencatat pesanan Anda dan membawanya ke dapur.
  • Web Server (WidyaWeb) adalah Koki di Dapur. Koki ini membaca pesanan Anda, mengambil bahan-bahan dari lemari pendingin (Basis Data / Database), memasaknya menjadi hidangan yang lezat, lalu menyerahkannya kembali ke pelayan untuk disajikan di hadapan Anda (menjadi tampilan halaman web di layar monitor).

Ketika Anda membuat program menggunakan WidyaWeb, tugas Anda adalah menjadi Kepala Koki yang mengatur: jika pelanggan memesan halaman Beranda, hidangan apa yang harus disajikan? Jika pelanggan mengirim formulir pendaftaran, bagaimana cara menyimpannya ke lemari basis data? Semuanya dilakukan secara teratur, bersih, dan cepat.

1.2 Mengapa Memilih WidyaWeb? (Zero-Dependency & Kedaulatan Digital)

Bagi seorang pemula, salah satu rintangan terbesar saat belajar pemrograman web adalah proses instalasi yang membingungkan (*environment setup hell*). Di framework konvensional, Anda sering diminta mengetikkan perintah-perintah misterius seperti: 

# Kerumitan lama yang TIDAK PERLU Anda lakukan di WidyaWeb:
npm install -g something
pip install virtualenv
composer require vendor/package
sudo apt-get install php-fpm mysql-server nginx ... (Bisa memakan waktu berjam-jam!)

Jika salah satu komponen versi library-nya bertabrakan (*version conflict*), program Anda akan langsung macet total dengan pesan galat merah yang sulit dimengerti.

WidyaWeb membuang semua kerumitan tersebut ke tempat sampah:

  1. Tanpa Instalasi Tambahan: Anda hanya membutuhkan satu file program bernama widya.exe di komputer Anda. Tidak perlu menginstal Node.js, tidak perlu menginstal Python, tidak perlu menginstal XAMPP.
  2. Sangat Hemat Memori: Saat berjalan, server WidyaWeb hanya memakai memori RAM sekitar 10 MB hingga 25 MB (bandingkan dengan framework lain yang sering menyedot 300 MB hingga 1 GB RAM laptop Anda). Laptop berspesifikasi sederhana pun dapat menjalankannya dengan sangat mulus.
  3. Kecepatan Eksekusi Sangat Tinggi: Karena mesin utamanya dibangun menggunakan Rust tingkat sistem, WidyaWeb mampu melayani ribuan pengunjung secara bersamaan dalam hitungan milidetik (*sub-millisecond latency*).

Buka folder baru AplikasiTokoSaya di VS Code. Anda akan melihat susunan file yang rapi. Jangan merasa kewalahan melihat banyaknya file! Mari kita analogikan susunan folder ini seperti ruangan-ruangan di sebuah toko:

AplikasiTokoSaya/ ├── 📄 main.wya ──► SAKLAR UTAMA (Tombol menyalakan seluruh sistem toko) ├── 📄 craft.wya ──► TONGKAT AJAIB (Alat bantu mengisi data & mengelola toko) ├── 📄 config.base.wya ──► BUKU CATATAN PENGATURAN (Nama toko, nomor port, dll.) │ ├── 📁 app/ ──► RUANG MESIN RAHASIA (Komponen inti pengaman, database, & server) ├── 📁 routes/ ──► PAPAN PETUNJUK ARAH (Mengatur rute alamat halaman web) ├── 📁 models/ ──► LEMBAR FORMAT DATA (Menentukan bentuk data barang, pembeli, dll.) ├── 📁 views/ ──► DEKORASI TOKO (Tampilan HTML yang dilihat mata pengunjung) ├── 📁 public/ ──► ETALASE TERBUKA (Gambar, foto produk, file CSS desain) ├── 📁 data/ ──► BRANKAS BESI (Tempat menyimpan file database toko yang aman) ├── 📁 logs/ ──► BUKU CATATAN CCTV (Merekam siapa saja yang masuk dan apa yang terjadi) └── 📁 .vscode/ ──► TOMBOL PINTAS EDITOR (Pengaturan khusus untuk VS Code Anda)

Dengan pembagian ruangan yang jelas ini, kode program Anda tidak akan pernah bercampur aduk menjadi "spaghetti code" yang ruwet. Anda selalu tahu persis di mana harus meletakkan kode baru:

  • Mau menambah alamat URL baru? Buka folder routes/.
  • Mau mengubah warna atau tata letak tombol halaman? Buka folder views/ atau public/.
  • Mau mengubah nomor port server atau nama website? Buka config.base.wya.

2.3 Memahami Berkas Pengaturan (config.base.wya)

Mari buka berkas config.base.wya di VS Code. Ini adalah pusat komando website Anda. Isinya menggunakan struktur kamus (*key-value pair*) yang sangat mudah dibaca: 

// config.base.wya - Pengaturan Dasar Aplikasi Anda
fungsi dapatkan_konfigurasi_dasar() {
    kembalikan {
        // 1. Nama Website yang Muncul di Judul Browser
        "nama_aplikasi": "Aplikasi Toko Saya",
        "versi": "1.0.0",

        // 2. Pengaturan Alamat Jaringan Komputer
        "server": {
            "host": "127.0.0.1",  // Alamat lokal laptop Anda (localhost)
            "port": 8080,          // Pintu gerbang port aplikasi
            "batas_muatan_mb": 10  // Batas maksimal ukuran unggah berkas (10 MB)
        },

        // 3. Pengaturan Basis Data Penyimpanan Data
        "database": {
            "driver": "sqlite",
            "path": "./data/aplikasi.db"  // Lokasi berkas tempat data disimpan
        },

        // 4. Pengaturan Keamanan & Sesi Pengguna
        "keamanan": {
            "durasi_sesi_detik": 7200 // 7200 detik = sesi login aktif selama 2 jam
        }
    };
}
💡 Apa itu Nomor Port (seperti 8080)?
Bayangkan komputer Anda adalah sebuah hotel berbintang. Alamat IP (seperti 127.0.0.1) adalah alamat gedung hotelnya. Sedangkan Port (seperti 8080) adalah Nomor Kamar di dalam hotel tersebut. Jika Anda menjalankan server di port 8080, browser Anda harus berkunjung ke kamar nomor 8080 untuk menemui website Anda.

Bab 3: Program Web Pertama ("Halo Dunia Web") & Siklus Hidup main.wya

3.1 Membedah Berkas main.wya Baris demi Baris

Mari buka berkas main.wya yang baru saja dibuat di proyek Anda. Berkas ini adalah "jantung" aplikasi Anda. Bagi orang awam, melihat kode pemrograman untuk pertama kali mungkin terasa asing, tetapi jika kita bedah satu per satu, logikanya sangat sederhana dan masuk akal: 

// ==============================================================================
// main.wya - Saklar Utama Aplikasi Web Anda
// ==============================================================================

// 1. MENGAMBIL ALAT-ALAT BANTU (IMPOR)
impor "./config.base.wya";        // Mengambil catatan nama website dan nomor port
impor "./app/logger.wya";         // Mengambil alat pencatat aktivitas (CCTV digital)
impor "./app/sanitizer.wya";      // Mengambil alat pembersih teks masukan
impor "./app/database.wya";       // Mengambil alat penghubung ke lemari basis data
impor "./app/web_framework.wya";  // Mengambil mesin web server utama
impor "./routes/api.wya";         // Mengambil daftar alamat rute API kita

// 2. MEMBUAT PROSEDUR UTAMA (FUNGSI UTAMA)
fungsi utama() {
    cetak("==================================================================");
    cetak("🚀 Memulai Server Toko Saya (WidyaWeb Framework)...");
    cetak("==================================================================");

    // A. Membaca pengaturan
    misal cfg = dapatkan_konfigurasi_dasar();
    misal port = cfg["server"]["port"];

    // B. Menyiapkan papan petunjuk arah (Router)
    misal router = buat_router();

    // C. Mendaftarkan Pintu Masuk Halaman Utama (Alamat "/")
    GET(router, "/", fungsi(req, res) {
        // Saat pengunjung membuka alamat utama, beri jawaban sambutan ini:
        kembalikan response_json(res, {
            "status": "AKTIF",
            "pesan": "Selamat datang di website Toko Saya!",
            "pemilik": "Saya Sendiri",
            "waktu_server": waktu()
        }, 200); // 200 artinya: Permintaan berhasil (OK)
    });

    // D. Mendaftarkan rute-rute tambahan dari berkas routes/api.wya
    daftarkan_rute_api(router);

    // E. Membuka pintu gerbang jaringan dan menyalakan server
    jalankan_server(router);
}

// 3. NYALAKAN APLIKASI SEKARANG
utama();

🔍 Penjelasan Rinci Bagian demi Bagian:

  1. Bagian impor: Di awal program, kita memanggil modul-modul yang dibutuhkan. Sama seperti koki yang mengambil pisau, wajan, dan bumbu dapur sebelum mulai memasak.
  2. buat_router(): Router adalah papan penunjuk jalan. Ketika pengunjung datang dan mengetik alamat di browsernya, router bertugas mengarahkan: "Oh, pengunjung ingin melihat Beranda, panggilkan fungsi Beranda! Pengunjung ingin melihat Daftar Produk, panggilkan fungsi Produk!".
  3. GET(router, "/", fungsi(req, res) { ... }): Garis miring "/" melambangkan halaman beranda utama website (pintu depan toko). Variabel req adalah surat permintaan dari pengunjung, dan res adalah amplop jawaban yang akan kita kirim kembali.
  4. jalankan_server(router): Ini adalah saklar pemancar. Perintah inilah yang membuat laptop Anda mulai mendengarkan koneksi jaringan dan melayani pengunjung.

3.3 Troubleshooting: Bagaimana Jika Muncul Pesan Galat?

⚠️ Port 8080 Sudah Terpakai (*Address already in use*)
Gejala: Di terminal muncul pesan "Only one usage of each socket address is normally permitted" atau gagal bind.
Penyebab: Ada aplikasi lain (atau jendela server Widya sebelumnya yang belum dimatikan) yang sedang memakai pintu kamar 8080.
Solusi Mudah: Cukup buka berkas config.base.wya, ubah angka 8080 menjadi 8090 atau 3000, lalu simpan berkas dan nyalakan kembali server Anda. Sekarang website Anda bisa diakses di http://localhost:8090/!

Bab 4: Sistem Routing (Membuat Rute & Pintu Masuk Halaman)

4.1 Apa itu Routing & Metode HTTP?

Ketika kita mengunjungi sebuah website (seperti toko online), kita tidak hanya berada di halaman depan. Kita ingin membuka halaman profil (/profil), halaman daftar barang (/produk), halaman keranjang belanja (/keranjang), atau mengirim formulir pemesanan. Proses pembagian alamat URL ini disebut Routing.

💡 Mengenal 4 Macam Metode HTTP Sehari-hari
Di dunia internet, browser berkomunikasi dengan server menggunakan beberapa "kata kerja" utama:
  • GET (Ambilkan Saya Data): Dipakai saat kita hanya ingin melihat atau membaca informasi tanpa mengubah apapun di server (contoh: membuka halaman berita, melihat katalog barang).
  • POST (Simpan Data Baru Ini): Dipakai saat kita mengirim data baru untuk disimpan ke server (contoh: mendaftar akun baru, mengirim komentar, memesan makanan).
  • PUT (Perbarui Data yang Ada): Dipakai saat kita ingin mengganti atau mengedit data yang sudah ada (contoh: mengganti foto profil, mengedit nomor telepon akun).
  • DELETE (Hapus Data Ini): Dipakai saat kita ingin membuang data (contoh: menghapus item dari keranjang belanja).

4.2 Membuat Berkas Rute Baru (routes/api.wya)

Mari buka berkas routes/api.wya. Di sini kita akan menambahkan beberapa pintu alamat baru untuk toko kita: 

// routes/api.wya - Daftar Rute API Toko Kita
fungsi daftarkan_rute_api(router) {

    // 1. Halaman Informasi Toko (GET /api/v1/tentang)
    GET(router, "/api/v1/tentang", fungsi(req, res) {
        kembalikan response_json(res, {
            "nama_toko": "Warung Berkah Digital",
            "jam_buka": "08:00 - 21:00 WIB",
            "lokasi": "Jakarta, Indonesia"
        }, 200);
    });

    // 2. Rute Dinamis dengan Parameter ID (GET /api/v1/produk/:id)
    GET(router, "/api/v1/produk/:id", fungsi(req, res) {
        // Mengambil nomor ID yang diketik pengunjung di browser
        misal id_barang = req["params"]["id"];

                "id": 1,
                "nama": "Kopi Robusta Nusantara",

                "stok": 50

        } kalau {

                "sukses": salah,
                "pesan": "Maaf, produk nomor " + id_barang + " belum tersedia"
            }, 404);
        }

    // 3. Rute Menerima Data Kiriman (POST /api/v1/pesan)

Bab 5: Satpam Pengaman Web (Pipeline Middleware & Keamanan)

5.1 Apa itu Middleware? (Analogi Pos Satpam Perumahan)

Bayangkan Anda tinggal di sebuah perumahan klaster tertutup (*gated community*). Di gerbang utama perumahan ada pos satpam:

PENGUNJUNG DATANG │ ▼ ┌────────────────────────────────────────────────────────┐ │ POS SATPAM UTAMA │ │ (Middleware Before Hook) │ │ 1. Periksa KTP & Identitas Pengunjung │ │ 2. Periksa apakah pengunjung membawa senjata tajam? │ │ 3. Catat plat nomor kendaraan ke buku tamu log │ └───────────────────────┬────────────────────────────────┘ │ Jika Lolos Pemeriksaan ▼ ┌────────────────────────────────────────────────────────┐ │ RUMAH TUJUAN / KAMAR │ │ (Handler Rute Anda) │ │ Menyiapkan hidangan & data yang diminta │ └───────────────────────┬────────────────────────────────┘ │ ▼ ┌────────────────────────────────────────────────────────┐ │ POS SATPAM KELUAR │ │ (Middleware After Hook) │ │ 4. Tempelkan stempel segel keamanan di amplop keluar │ │ 5. Pasang 6 Tameng HTTP Security Headers │ └────────────────────────────────────────────────────────┘ │ ▼ PENGUNJUNG PULANG MEMBAWA JAWABAN AMAN

Di dalam WidyaWeb, Middleware adalah kode yang berjalan otomatis sebelum atau sesudah fungsi halaman web Anda dipanggil. Middleware memastikan bahwa fungsi bisnis Anda (seperti menghitung total belanja) tidak perlu dipusingkan dengan urusan keamanan, karena satpam middleware telah menyaringnya terlebih dahulu di gerbang depan.

5.2 Enam Tameng Keamanan Bawaan (Menjaga Anda Tanpa Pusing)

Setiap jawaban yang keluar dari WidyaWeb otomatis ditempeli 6 tameng pelindung tingkat perbankan:

  1. Tameng Anti-Pembajakan Bingkai (X-Frame-Options: DENY): Mencegah penjahat siber membungkus website Anda di dalam situs palsu untuk menipu klik tombol perbankan (*Clickjacking attack*).
  2. Tameng Anti-Manipulasi Tipe Berkas (X-Content-Type-Options: nosniff): Memaksa browser membaca file teks murni sebagai teks, dan tidak tertipu menjalankan file berbahaya yang menyamar sebagai gambar.
  3. Tameng Kebijakan Keamanan Konten Ketat (Content-Security-Policy): Membatasi agar browser hanya mengeksekusi skrip dari sumber terpercaya, sehingga virus atau injeksi kode jahat (*Cross-Site Scripting / XSS*) otomatis ditolak oleh browser.
  4. Tameng Jalur Aman Terenkripsi (Strict-Transport-Security): Menjamin komunikasi selalu lewat jalur gembok hijau HTTPS yang terenkripsi.

5.3 Membatasi Pengunjung Nakal dengan Rate Limiter

Pernahkah Anda mendengar tentang serangan Brute-Force? Di mana peretas menggunakan robot komputer untuk menebak kata sandi login 1.000 kali dalam satu detik?

WidyaWeb memiliki sistem Rate Limiter Bawaan. Jika ada satu alamat IP komputer yang meminta akses terlalu sering melebihi batas wajar (misal lebih dari 120 kali dalam 1 menit), server WidyaWeb akan langsung memberi kartu merah: 

{
  "sukses": false,
  "galat": "Terlalu banyak permintaan. Silakan coba lagi setelah 60 detik.",
  "kode_galat": "RATE_LIMIT_TERCAPAI"
}

Dengan tameng ini, server Anda tetap tenang, tidak akan kehabisan tenaga, dan terhindar dari kelumpuhan akibat serangan robot botnet (*Denial of Service*).

Bab 6: Menyimpan Data Permanen (Basis Data & Fluent ORM)

6.1 Mengapa Kita Membutuhkan Basis Data?

Jika Anda hanya menyimpan data di dalam variabel program (misal: misal nama = "Budi";), saat server komputer Anda dimatikan atau laptop Anda restart, seluruh data tersebut akan langsung lenyap tak berbekas!

Basis Data (Database) adalah lemari arsip baja yang bertugas menyimpan data secara permanen ke dalam piringan harddisk. Kapanpun komputer dinyalakan kembali, catatan data pelanggan, pesanan, dan transaksi Anda tetap aman tersimpan rapi.

6.2 Membaca Data Semudah Berbahasa Manusia (Fluent ORM db_dari)

Di zaman dulu, untuk membaca data dari tabel, programmer harus mengetik perintah SQL yang kaku seperti SELECT id, nama, harga FROM produk WHERE harga > 10000 ORDER BY id DESC LIMIT 20;. Jika salah satu tanda koma atau spasi saja, program akan langsung error.

Di WidyaWeb, Anda cukup menggunakan Fluent Query Builder db_dari() yang mengalir wajar seperti kalimat bahasa manusia: 

// Contoh Membaca Data Produk dengan db_dari()
misal daftar_produk = db_dari("produk")
    .pilih(["id", "nama", "harga", "stok"])  // Kolom apa saja yang ingin diambil?
    .dimana("kategori", "minuman")            // Hanya ambil yang kategorinya minuman
    .dimana_lebih_dari("harga", 15000)        // Dan yang harganya di atas Rp 15.000
    .urutkan("harga", "DESC")                  // Urutkan dari harga paling mahal
    .paginasi(1, 10);                         // Tampilkan halaman 1 (10 barang per halaman)

6.3 Menambah, Mengubah, dan Menghapus Data (Operasi CRUD)

Mari pelajari 4 operasi paling penting dalam pengelolaan data: 

// 1. MENAMBAH DATA BARU (CREATE)
db_jalan("INSERT INTO produk (nama, harga, stok) VALUES (?, ?, ?)",
         ["Teh Melati Segar", 12000, 100]);

// 2. MEMBACA SATU DATA SPESIFIK (READ)
misal barang = db_dari("produk").dimana("id", 1).pertama();
cetak("Nama Barang: " + barang["nama"]);

// 3. MENGUBAH / MEMPERBARUI DATA (UPDATE)
db_jalan("UPDATE produk SET stok = ? WHERE id = ?", [85, 1]);

// 4. MENGHAPUS DATA (DELETE)
db_jalan("DELETE FROM produk WHERE id = ?", [99]);

6.4 Transaksi Atomik: Menjamin Uang Tidak Hilang di Tengah Jalan!

Bayangkan Anda sedang mentransfer uang sebesar Rp 100.000 dari rekening Andi ke rekening Budi. Ada 2 langkah yang harus terjadi:
1. Saldo Andi dipotong Rp 100.000.
2. Saldo Budi ditambah Rp 100.000.

Bagaimana jika tepat setelah saldo Andi dipotong, tiba-tiba listrik padam atau koneksi server terputus sebelum saldo Budi bertambah? Uang Rp 100.000 itu akan raib di antah berantah!

WidyaWeb menyelesaikan masalah ini dengan Transaksi Atomik ACID (db_transaksi): 

// Transaksi Keuangan Aman Terpadu
misal sukses = db_transaksi(fungsi(tx) {
    // Langkah 1: Kurangi uang Andi
    tx.eksekusi("UPDATE dompet SET saldo = saldo - 100000 WHERE nama = 'Andi'", []);

    // Langkah 2: Tambahkan uang Budi
    tx.eksekusi("UPDATE dompet SET saldo = saldo + 100000 WHERE nama = 'Budi'", []);

    kembalikan benar;
});
// Jika salah satu langkah gagal, seluruh perubahan otomatis DIBATALKAN (Rollback)
// seolah-olah tidak pernah terjadi apa-apa. Saldo Andi tetap utuh 100%!

Bab 7: Sistem Login Pengguna, Sandi Argon2id & Hak Akses (RBAC)

7.1 Mengapa Menyimpan Kata Sandi Biasa Adalah Kejahatan Siber?

Bagi orang yang baru pertama kali belajar membuat website, salah satu kesalahan paling fatal yang sering dilakukan adalah menyimpan kata sandi pengguna apa adanya (disebut teks mentah atau plain text) ke dalam basis data. Bayangkan skenario berikut:

⚠️ Bahaya Fatal Menyimpan Sandi Polos
Jika seorang pengguna mendaftar dengan kata sandi Rahasia123! dan Anda menyimpannya begitu saja ke dalam tabel, maka setiap orang yang memiliki akses ke server—atau jika suatu saat server Anda berhasil ditembus oleh peretas—kata sandi tersebut akan langsung terbaca! Parahnya lagi, banyak pengguna menggunakan kata sandi yang sama untuk akun email dan rekening bank mereka.

Untuk mencegah hal tersebut, para ahli kriptografi dunia menciptakan teknik yang disebut Fungsi Hashing Satu Arah (One-Way Hashing).

💡 Analogi Mesin Penggiling Daging vs Kunci Brankas
  • Enkripsi Biasa (Dua Arah) diibaratkan seperti Kunci Gembok. Anda mengunci dokumen penting ke dalam brankas, dan suatu hari Anda bisa membukanya kembali menggunakan anak kunci yang sama.
  • Hashing Satu Arah (Argon2id) diibaratkan seperti Mesin Penggiling Daging. Anda memasukkan potongan daging sapi segar (kata sandi asli), lalu mesin menggilingnya menjadi sosis cincang berlumur bumbu rahasia (string hash acak). Sekali daging itu menjadi sosis cincang, tidak ada ilmuwan atau teknologi manapun di dunia yang bisa mengubah sosis tersebut kembali utuh menjadi sapi hidup!

Lalu bagaimana server tahu bahwa kata sandi yang diketik saat login sudah benar jika server tidak tahu bentuk aslinya? Caranya sangat cerdas: Saat pengguna login dan mengetikkan sandi, server memasukkan sandi ketikan tersebut ke mesin penggiling yang sama. Jika hasil sosis cincangnya identik persis dengan sosis yang tersimpan di lemari data, berarti sandinya pasti benar!

Mengapa WidyaWeb Memilih Argon2id (Bukan MD5 atau SHA-1)?

Algoritma lama seperti MD5 atau SHA-1 sudah tidak boleh digunakan lagi di dunia industri modern. Mengapa? Karena komputer modern dengan kartu grafis (GPU) dapat menebak miliaran kombinasi MD5 per detik (serangan brute-force).

WidyaWeb menggunakan Argon2id, pemenang resmi kompetisi internasional Password Hashing Competition. Argon2id dirancang secara Memory-Hard: algoritma ini sengaja memakan memori RAM komputer saat melakukan penggilingan. Hal ini membuat peretas yang menggunakan superkomputer sekalipun akan kehabisan memori dan bangkrut membayar listrik sebelum berhasil menebak sandi pengguna Anda.

7.2 Mendaftarkan Akun Baru & Memverifikasi Login

Di dalam berkas app/auth.wya, WidyaWeb menyediakan fungsi bawaan untuk menangani pendaftaran anggota baru dan verifikasi login dengan keamanan tingkat tinggi. Perhatikan kode di bawah ini: 

// ==============================================================================
// app/auth.wya - Modul Otentikasi & Keamanan Akun Pengguna
// ==============================================================================
impor "./database.wya";
impor "./logger.wya";

// FUNGSI 1: Mendaftarkan Akun Anggota Baru
fungsi daftarkan_pengguna(email, kata_sandi_mentah, peran) {
    // 1. Pastikan kata sandi memiliki panjang yang cukup aman (minimal 8 karakter)
    jika (panjang(kata_sandi_mentah) < 8) {
        kembalikan {"sukses": salah, "pesan": "Kata sandi minimal harus 8 karakter!"};
    }

    // 2. Giling kata sandi menggunakan Argon2id (menghasilkan string hash acak & aman)
    misal hash_terenkripsi = argon2id_hash(kata_sandi_mentah);

    // 3. Simpan ke tabel pengguna di basis data SQLite
    coba {
        db_jalan("INSERT INTO pengguna (email, hash_sandi, peran, dibuat_pada) VALUES (?, ?, ?, datetime('now'))",
                 [email, hash_terenkripsi, peran]);
        
        log_info("Pengguna baru berhasil didaftarkan: " + email + " (Peran: " + peran + ")");
        kembalikan {"sukses": benar, "pesan": "Akun berhasil dibuat!"};
    } tangkap (galat) {
        log_peringatan("Gagal mendaftarkan akun (mungkin email sudah ada): " + galat);
        kembalikan {"sukses": salah, "pesan": "Email sudah terdaftar, silakan gunakan email lain."};
    }
}

// FUNGSI 2: Memverifikasi Kredensial Saat Pengguna Ingin Masuk (Login)
fungsi otentikasi_masuk(email, kata_sandi_klien) {
    // 1. Cari data pengguna berdasarkan email
    misal user = db_dari("pengguna").dimana("email", email).pertama();

    // Jika email tidak ditemukan sama sekali di lemari data:
    jika (user == nil) {
        log_peringatan("Percobaan login gagal: Email tidak dikenal - " + email);
        kembalikan nil;
    }

    // 2. Masukkan kata sandi ketikan pengguna ke pembanding Argon2id
    misal cocok = argon2id_verifikasi(kata_sandi_klien, user["hash_sandi"]);

    // Jika cocok sempurna:
    jika (cocok) {
        log_info("Pengguna berhasil login: " + email);
        kembalikan user; // Kembalikan data profil pengguna
    }

    // Jika kata sandi salah:
    log_peringatan("Percobaan login gagal: Sandi keliru untuk - " + email);
    kembalikan nil;
}

🔍 Bedah Logika untuk Pemula:

  1. Fungsi argon2id_hash(sandi): Mengambil kata sandi mentah (misal: "kopiTubruk2026") dan secara otomatis menambahkan salt (garam kriptografis acak) lalu mengembalikannya menjadi kode rahasia sepanjang ~90 karakter, misalnya $argon2id$v=19$m=65536,t=3,p=4$dGVzdHNhbHQ.... Di dalam database, yang tersimpan hanyalah deretan kode acak ini.
  2. Fungsi argon2id_verifikasi(mentah, hash): Fungsi ini bertugas membandingkan secara matematis apakah kata sandi mentah yang baru diketik oleh pengunjung menghasilkan struktur hash yang sama dengan yang ada di lemari data. Jika sama, fungsi menghasilkan nilai benar (true); jika salah, menghasilkan salah (false).

7.3 Sesi Pengguna: Bagaimana Server Mengingat Pengunjung?

Protokol HTTP yang menjadi tulang punggung internet memiliki sifat dasar yang unik: Stateless (Pelupa). Artinya, setiap kali peramban meminta halaman baru, server menganggap permintaan tersebut datang dari orang asing yang belum pernah bertemu sebelumnya!

💡 Analogi Gelang Tiket Taman Rekreasi
Bayangkan Anda berkunjung ke Dufan atau Ancol:
  • Saat di gerbang masuk utama, Anda membeli tiket dan menunjukkan KTP (Proses Login).
  • Petugas memasangkan Gelang Kertas Bersegel Barcode di pergelangan tangan Anda (disebut Session Cookie).
  • Sepanjang hari, saat Anda ingin naik wahana Roller Coaster atau Kora-Kora, Anda tidak perlu lagi menunjukkan KTP dan membayar tiket ulang. Anda cukup menunjukkan gelang tiket tersebut kepada petugas wahana (Server).
  • Ketika Anda selesai bermain dan pulang ke rumah, Anda menggunting gelang tersebut (Proses Logout).

Di dalam WidyaWeb, gelang tiket ini dikirimkan ke peramban pengunjung sebagai Cookie yang dilindungi dengan 3 tameng pengaman wajib:

🛡️ 3 Tameng Pengaman Cookie Sesi WidyaWeb
  1. HttpOnly = true: Cookie hanya boleh dibaca oleh server web melalui jaringan internet. Kode JavaScript peramban tidak diizinkan menyentuhnya sama sekali. Ini membuat hacker tidak bisa mencuri sesi Anda meskipun mereka mencoba menyusupkan skrip jahat (kebal XSS).
  2. SameSite = Strict: Cookie hanya akan dikirimkan jika pengguna benar-benar membuka website Anda secara langsung, bukan melalui tautan jebakan dari situs luar (kebal pemalsuan permintaan CSRF).
  3. Secure = true: Pada mode produksi nyata, cookie hanya akan meluncur jika koneksi terenkripsi oleh gembok hijau HTTPS.

7.4 Pembagian Peran dan Wewenang (RBAC: Role-Based Access Control)

Di sebuah kantor atau perusahaan, tidak semua orang memiliki hak yang sama. Seorang kasir hanya boleh mengakses mesin kasir, sedangkan ruang brankas keuangan hanya boleh dibuka oleh manajer atau direktur. Sistem pengaturan hak akses seperti ini disebut Role-Based Access Control (RBAC).

┌────────────────────────────────────────────────────────┐ │ MATRIKS WEWENANG PENGGUNA (RBAC) │ ├──────────────┬──────────────┬─────────────┬────────────┤ │ PERAN (ROLE) │ BUKA PRODUK │ TRANSAKSI │ PANEL ADMIN│ ├──────────────┼──────────────┼─────────────┼────────────┤ │ Pengunjung │ ✅ Boleh │ ❌ Dilarang│ ❌ Dilarang│ │ Kasir │ ✅ Boleh │ ✅ Boleh │ ❌ Dilarang│ │ Administrator│ ✅ Boleh │ ✅ Boleh │ ✅ Boleh │ └──────────────┴──────────────┴─────────────┴────────────┘

Untuk menjaga agar halaman-halaman rahasia tidak bisa diintip sembarangan, kita memasang Middleware Penjaga Gerbang (Guard) pada rute yang bersangkutan: 

// Middleware: Satpam Pintu Khusus Administrator
fungsi satpam_khusus_admin(req, res, lanjut) {
    // 1. Periksa apakah pengunjung sudah login (memiliki sesi aktif)
    misal sesi = req["sesi"];
    jika (sesi == nil atau sesi["pengguna_id"] == nil) {
        // Jika belum login sama sekali, usir dengan kode HTTP 401 Unauthorized
        kembalikan response_json(res, {
            "sukses": salah,
            "pesan": "Akses ditolak: Anda harus login terlebih dahulu!"
        }, 401);
    }

    // 2. Periksa apakah peran di dalam tiket sesi adalah "admin"
    jika (sesi["peran"] != "admin") {
        // Jika dia sudah login tetapi perannya hanya kasir/pengunjung biasa,
        // tolak dengan kode HTTP 403 Forbidden (Terlarang)
        log_peringatan("Akses ilegal terdeteksi oleh user ID " + sesi["pengguna_id"]);
        kembalikan response_json(res, {
            "sukses": salah,
            "pesan": "Akses dilarang: Fitur ini hanya untuk Administrator!"
        }, 403);
    }

    // 3. Jika lolos seluruh pemeriksaan, persilakan lanjut masuk
    kembalikan lanjut(req, res);
}

Bab 8: Validasi Formulir Deklaratif (HTTP 422) & Dokumentasi API Otomatis

8.1 Menghindari "Sampah Masuk, Sampah Keluar" (Garbage In, Garbage Out)

Salah satu prinsip paling kuno namun terpenting dalam dunia pemrograman adalah: Jangan Pernah Percaya pada Data Kiriman Pengguna!

💡 Analogi Petugas Loket Pendaftaran SIM
Bayangkan Anda mendaftar SIM di kantor kepolisian. Di formulir tertulis:
  • Kolom NIK harus berisi tepat 16 digit angka.
  • Kolom Umur harus berupa angka minimal 17 tahun.
Jika ada pemohon yang mengisi kolom NIK dengan tulisan "Kucing Lucu" atau mengisi umur dengan angka minus sepuluh (-10), apakah petugas loket akan meloloskannya ke ruangan ujian praktik mengemudi? Tentu saja tidak! Petugas loket akan langsung mencoret formulir itu dan berkata: "Maaf, formulir Anda belum lengkap dan salah isi. Perbaiki bagian NIK dan umur Anda sekarang."

Di dalam WidyaWeb, petugas loket pemeriksa ini disebut Mesin Validasi Deklaratif. Alih-alih membuat puluhan baris logika jika... maka... yang membingungkan dan rawan terlewat, Anda cukup mendeklarasikan aturan mainnya dalam satu baris sederhana.

8.2 Aturan Validasi Bawaan & Respon Standar HTTP 422

Berikut adalah tabel aturan validasi praktis yang siap Anda gunakan kapan saja:

Aturan Validasi Arti & Batasan Contoh Pemakaian
wajib Data tidak boleh kosong (harus diisi). "nama": "wajib"
email Harus berformat alamat email valid (ada tanda @ dan titik). "email": "wajib|email"
angka Harus berupa bilangan bulat atau desimal. "harga": "wajib|angka"
min:N Nilai angka minimal N atau panjang teks minimal N huruf. "sandi": "wajib|min:8"
max:N Nilai angka maksimal N atau panjang teks maksimal N huruf. "nama": "wajib|max:50"
panjang:N Panjang karakter harus tepat sebanyak N karakter. "nik": "wajib|angka|panjang:16"

Contoh Penerapan Nyata pada Rute Pendaftaran Anggota Koperasi:

// routes/api.wya - Endpoint Pendaftaran Anggota Koperasi Baru
POST(router, "/api/v1/koperasi/daftar", fungsi(req, res) {
    // 1. Tentukan aturan validasi yang wajib ditaati
    misal aturan_skema = {
        "nik": "wajib|angka|panjang:16",
        "nama_lengkap": "wajib|teks|min:3|max:100",
        "email": "wajib|email",
        "simpanan_pokok": "wajib|angka|min:100000"
    };

    // 2. Jalankan mesin pemeriksa terhadap data kiriman pengunjung
    misal data_kiriman = req["badan"];
    misal daftar_galat = validasi_skema(data_kiriman, aturan_skema);

    // 3. Jika ada kolom yang melanggar aturan, tolak dengan HTTP 422
    jika (panjang(daftar_galat) > 0) {
        kembalikan response_json(res, {
            "sukses": salah,
            "pesan": "Formulir pendaftaran tidak valid!",
            "rincian_kesalahan": daftar_galat
        }, 422); // 422: Unprocessable Entity
    }

    // 4. Jika semua data lolos sensor, masukkan ke lemari database
    db_jalan("INSERT INTO anggota (nik, nama, email, saldo) VALUES (?, ?, ?, ?)",
             [data_kiriman["nik"], data_kiriman["nama_lengkap"], data_kiriman["email"], data_kiriman["simpanan_pokok"]]);

    kembalikan response_json(res, {
        "sukses": benar,
        "pesan": "Selamat! Anda resmi terdaftar sebagai anggota koperasi."
    }, 201); // 201: Created (Berhasil Dibuat)
});
🎯 Hasil Respon Saat Terjadi Kesalahan (HTTP 422)

  "sukses": false,
  "pesan": "Formulir pendaftaran tidak valid!",
  "rincian_kesalahan": [
    "Kolom 'nik' harus tepat memiliki panjang 16 karakter.",
    "Nilai kolom 'simpanan_pokok' minimal harus 100000."
  ]

Bab 10: Komunikasi Real-Time (Server-Sent Events & WebSocket)

10.1 Perbedaan Web Biasa (Klien Bertanya) vs Web Real-Time (Server Menyiarkan)

Mari kita pelajari perbedaan mendasar antara cara kerja web tradisional dan web modern yang serba langsung (Real-Time):

💡 Analogi Menunggu Pengumuman Kereta Api
  • Web Tradisional (Polling Berulang): Anda berdiri di depan loket informasi stasiun dan setiap 5 detik Anda bertanya kepada petugas: "Pak, apakah kereta dari Surabaya sudah datang? Belum. Pak, apakah sudah datang? Belum. Pak, apakah sudah datang?". Tindakan ini membuat Anda capek, petugas stasiun jengkel, dan antrean di loket menjadi macet total.
  • Web Real-Time (Server-Sent Events / Push): Petugas stasiun memasang Pengeras Suara (Loudspeaker) di ruang tunggu. Anda bisa duduk santai membaca koran tanpa perlu mondar-mandir ke loket. Begitu kereta tiba, petugas membunyikan pengeras suara: "Perhatian, kereta dari Surabaya telah tiba di Jalur 3!". Suara itu langsung terdengar oleh Anda detik itu juga!

10.2 Server-Sent Events (SSE): Cara Termudah Mengirim Data Berjalan

Banyak pemula mengira bahwa untuk membuat fitur data langsung (seperti notifikasi pesanan masuk pada layar kasir restoran, grafik beban CPU server, atau lonceng pemberitahuan pesan baru) kita harus membuat sistem yang rumit. Padahal tidak!

WidyaWeb menyediakan teknologi berstandar W3C bernama Server-Sent Events (SSE). Melalui SSE, server menjaga sebuah saluran komunikasi tetap terbuka ke peramban dan bisa mengirimkan data kapan saja: 

// app/sse.wya - Endpoint Aliran Notifikasi Kasir Real-Time
GET(router, "/api/sse/kasir/notifikasi", fungsi(req, res) {
    // 1. Buka pipa aliran SSE ke layar peramban kasir
    misal pipa_aliran = buka_kanal_sse(res);

    // 2. Kirim pesan selamat datang pertama saat terhubung
    pipa_aliran.kirim_event("tersambung", {
        "status": "TERKONEKSI",
        "pesan": "Layar kasir berhasil terhubung ke antena siaran dapur!",
        "waktu": waktu()
    });

    // 3. Pasang telinga pada Bus Peristiwa internal (Event Bus)
    // Setiap kali ada pesanan baru masuk dari meja pelanggan:
    bus_dengarkan("pesanan_baru_masuk", fungsi(data_pesanan) {
        // Siarkan langsung ke layar kasir detik itu juga!
        pipa_aliran.kirim_event("pesanan_masuk", data_pesanan);
    });

    // 4. Tahan koneksi agar tidak ditutup otomatis oleh HTTP biasa
    kembalikan pipa_aliran.tahan_koneksi();
});

Cara Menangkap Siaran Ini di Layar Browser (JavaScript Sederhana):

Di halaman web peramban kasir, Anda hanya perlu menulis 5 baris JavaScript super sederhana ini di dalam berkas HTML: 

<script>
  // Membuka antena penerima sinyal ke server WidyaWeb kita
  const radio = new EventSource('/api/sse/kasir/notifikasi');

  // Menangkap siaran 'pesanan_masuk'
  radio.addEventListener('pesanan_masuk', function(event) {
    const pesanan = JSON.parse(event.data);
    
    // Bunyikan notifikasi lonceng atau munculkan pop-up di layar
    alert("🔔 Pesanan Baru Masuk dari Meja " + pesanan.nomor_meja + ": " + pesanan.nama_menu);
  });
</script>
🎯 Kapan Harus Memilih Antara SSE vs WebSocket?
  • Pilih SSE (Server-Sent Events): Jika Anda hanya butuh pengiriman data dari Server ke Klien (Satu Arah). Sangat cocok untuk: Notifikasi lonceng web, live feed twitter/berita, monitoring kasir, ticker harga emas/kripto, atau log aktivitas sistem. Sangat hemat memori dan otomatis menyambung ulang jika internet ponsel sempat putus!
  • Pilih WebSocket: Jika Anda butuh komunikasi dua arah berkecepatan milidetik tanpa henti. Sangat cocok untuk: Game online tembak-menembak multipemain atau aplikasi video call / live group chat.

Bab 11: Pekerjaan Latar Belakang (Job Queue), Event Bus & Webhook

11.1 Mengapa Website Tidak Boleh "Membeku" Menunggu Tugas Berat?

Ketika seorang pengunjung menekan tombol "Beli Sekarang" atau "Daftar Akun Baru" di website Anda, mereka mengharapkan halaman web merespons seketika dalam hitungan kurang dari 1 detik. Namun, bayangkan apa saja yang harus dilakukan oleh server di balik layar:

  1. Menyimpan data transaksi ke lemari basis data (sangat cepat, hanya butuh 2 milidetik).
  2. Membuat berkas struk invoice PDF setebal 5 halaman lengkap dengan gambar barcode (memakan waktu 4 detik).
  3. Mengirimkan email verifikasi lewat server pos internet ke penyedia email pengunjung (memakan waktu 3 detik).
  4. Menghubungi server gudang logistik eksternal untuk menyiapkan kurir penjemputan barang (memakan waktu 5 detik).
⚠️ Bahaya Memproses Semua Tugas Sekaligus (Sinkron)
Jika keempat tugas di atas diproses secara berurutan saat itu juga di depan pengunjung, maka pengunjung harus menunggu layar berputar-putar (loading freeze) selama 12 detik penuh! Pengunjung yang tidak sabar akan mengira website Anda rusak atau ponsel mereka sedang macet, lalu mereka akan menekan tombol beli berkali-kali atau menutup peramban mereka.
💡 Analogi Layanan Cepat Restoran Cepat Saji (Drive-Thru)
Perhatikan cara kerja kasir restoran cepat saji:
  • Anda memesan 5 porsi ayam goreng krispi dan 2 burger ke kasir.
  • Kasir tidak menyuruh Anda berdiri di depan meja kasir sampai ayam selesai digoreng selama 15 menit.
  • Kasir segera memberikan struk bukti pembayaran beserta Nomor Antrean Anda (Respons Instan HTTP 200). Anda dipersilakan duduk santai di ruang tunggu.
  • Sementara itu, pesanan Anda dikirimkan lewat lembar kertas kecil ke Dapur Belakang (Antrean Pekerjaan / Job Queue). Para juru masak di dapur belakang menggoreng ayam Anda tanpa memblokir pelanggan lain yang ingin memesan di meja kasir.
  • Saat ayam matang, pelayan memanggil nomor antrean Anda.

11.2 Antrean Asinkron (Job Queue) di WidyaWeb

WidyaWeb menyediakan sistem antrean asinkron bawaan yang disimpan secara persisten di dalam disk komputer. Tugas-tugas berat cukup didorong ke antrean menggunakan perintah antrean_dorong: 

// routes/api.wya - Endpoint Pendaftaran yang Sangat Cepat Responsnya
POST(router, "/api/v1/pengguna/daftar", fungsi(req, res) {
    misal data = req["badan"];

    // 1. Simpan data pengguna ke basis data SQLite (instan, ~2ms)
    db_jalan("INSERT INTO pengguna (email, nama) VALUES (?, ?)", [data["email"], data["nama"]]);

    // 2. Lempar tugas berat (kirim email selamat datang) ke antrean dapur belakang!
    antrean_dorong("kirim_email_selamat_datang", {
        "email_tujuan": data["email"],
        "nama_penerima": data["nama"],
        "waktu_antre": waktu()
    });

    // 3. Langsung beri jawaban sukses ke pengunjung tanpa menunggu email terkirim!
    kembalikan response_json(res, {
        "sukses": benar,
        "pesan": "Pendaftaran berhasil! Email sambutan sedang meluncur ke kotak masuk Anda."
    }, 201);
});

Tugas yang dimasukkan ke dalam antrean akan dikerjakan oleh pekerja latar belakang (worker process) secara independen. Anda dapat menjalankan pekerja latar belakang ini kapan saja menggunakan alat baris perintah:

11.3 Event Bus: Sistem Pengeras Suara Internal Aplikasi

Saat aplikasi Anda berkembang menjadi besar, komponen-komponen program tidak boleh saling mengikat erat satu sama lain (disebut Tightly Coupled).

💡 Analogi Pengeras Suara Mall (Pusat Perbelanjaan)
Bayangkan di sebuah pusat perbelanjaan terdengar pengumuman dari pengeras suara: "Perhatian, seorang anak kecil berbaju merah sedang mencari orang tuanya di pusat informasi."
  • Petugas keamanan (Satpam) yang mendengar pengumuman itu langsung bersiaga di pintu keluar.
  • Petugas kebersihan tetap menyapu lantai karena itu bukan urusannya.
  • Ibu dari anak tersebut langsung bergegas menuju pusat informasi.
Bagian pusat informasi tidak perlu repot-repot menelepon satpam, petugas kebersihan, dan sang ibu satu per satu secara manual. Mereka cukup menyiarkan satu peristiwa (Event), dan pihak yang berkepentingan akan merespons secara mandiri!

Di WidyaWeb, Anda cukup menggunakan bus_pancarkan untuk mengumumkan sebuah peristiwa, dan bus_dengarkan untuk meresponsnya: 

// 1. Di bagian mana saja yang memproses transaksi sukses:
bus_pancarkan("transaksi_sukses", {
    "id_transaksi": 1042,
    "total": 250000,
    "pelanggan": "Budi Santoso"
});

// 2. Di modul inventaris (mengurangi stok barang):
bus_dengarkan("transaksi_sukses", fungsi(data) {
    kurangi_stok_gudang(data["id_transaksi"]);
});

// 3. Di modul telemetri (memperbarui angka penjualan di layar kasir secara real-time):
bus_dengarkan("transaksi_sukses", fungsi(data) {
    perbarui_grafik_kasir(data["total"]);
});

11.4 Webhook Outbound dengan Tanda Tangan Kriptografis HMAC-SHA256

Bagaimana jika website Anda perlu memberi tahu sistem komputer milik mitra bisnis (misalnya bank penyedia pembayaran QRIS atau jasa kurir ekspedisi)? Cara standar industri untuk melakukannya adalah dengan mengirimkan Webhook.

🛡️ Menjamin Surat Dinas Asli dengan Tanda Tangan Digital
Saat server Anda mengirim data transaksi ke server mitra melalui internet terbuka, bagaimana server mitra yakin bahwa kiriman data tersebut benar-benar berasal dari website resmi Anda dan bukan dipalsukan oleh peretas?

WidyaWeb menandatangani setiap kiriman webhook menggunakan algoritma HMAC-SHA256 dengan Kunci Rahasia Bersama (Shared Secret Key). Tanda tangan kriptografis ini disertakan pada header X-Hub-Signature-256 sehingga tidak dapat dipalsukan sedikit pun oleh peretas di tengah jalan. 
// app/webhook.wya - Pengiriman Laporan Transaksi ke Server Mitra
fungsi siarkan_webhook_transaksi(url_mitra, data_transaksi, kunci_rahasia) {
    // 1. Ubah paket data transaksi menjadi teks JSON
    misal payload_json = ke_json(data_transaksi);

    // 2. Buat stempel segel lilin digital (HMAC-SHA256) menggunakan kunci rahasia
    misal signature = hmac_sha256(kunci_rahasia, payload_json);

    // 3. Luncurkan paket data melalui protokol HTTP POST
    misal hasil = http_post_detil(url_mitra, {
        "headers": {
            "Content-Type": "application/json",
            "X-Hub-Signature-256": "sha256=" + signature
        },
        "body": payload_json,
        "timeout_ms": 5000 // Batas tunggu maksimal 5 detik
    });

    kembalikan hasil;
}

Bab 14: Membawa Website ke Internet Nyata (Hosting VPS, HTTPS & UU PDP)

14.1 Dari Komputer Sendiri (Localhost) ke Seluruh Dunia (Public IP & VPS)

Selama belajar di bab-bab sebelumnya, website Anda beralamat di http://localhost:8080 atau http://127.0.0.1:8080. Alamat ini hanya bisa dibuka oleh komputer Anda sendiri. Orang lain di internet belum bisa melihatnya.

💡 Analogi Toko di Garasi Rumah vs Ruko di Jalan Protokol
  • Localhost (Komputer Anda) ibaratnya Anda membuka toko roti di dalam garasi rumah Anda sendiri yang pagarnya terkunci rapat. Hanya anggota keluarga di rumah yang bisa melihat dan membeli roti tersebut.
  • Server VPS (Virtual Private Server) ibaratnya Anda menyewa ruko di pinggir jalan raya protokol yang dilewati ribuan orang setiap menit. Siapa saja dari seluruh penjuru dunia bisa datang, melihat plang nama toko Anda (Nama Domain, misal: www.tokosaya.id), dan masuk berbelanja selama 24 jam sehari 7 hari seminggu.

Anda dapat menyewa server VPS Linux murah dari penyedia lokal Indonesia (seperti IDCloudHost, Biznet Gio, atau Niagahoster) dengan biaya sangat terjangkau mulai dari Rp 50.000 hingga Rp 100.000 per bulan.

14.2 Menjaga Server Tetap Menyala 24 Jam Non-Stop dengan systemd

Di komputer laptop Anda, jika Anda menutup jendela terminal atau mematikan laptop, maka website Anda akan otomatis mati. Di server internet (VPS Linux), website Anda harus tetap menyala siang dan malam bahkan jika server mengalami mati listrik sesaat atau baru saja melakukan restart pembaruan sistem.

Untuk itu, kita mendaftarkan aplikasi WidyaWeb sebagai layanan latar belakang resmi Linux yang disebut Layanan systemd Daemon.

Membuat Berkas Layanan: /etc/systemd/system/widyaweb.service

[Unit]
Description=Layanan WidyaWeb Enterprise Server Berdaulat
After=network.target

[Service]
Type=simple
User=widya
WorkingDirectory=/opt/aplikasi_saya
ExecStart=/opt/widya-lang/widya main.wya
Restart=always
RestartSec=3
Environment=WIDYA_ENV=prod
Environment=PORT=8080

# Tameng Pengerasan Keamanan Sistem Operasi Linux (Hardening)
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full

[Install]
WantedBy=multi-user.target

🔍 Penjelasan Perintah Pengaturan di Atas:

  • Restart=always: Jika aplikasi tiba-tiba crash karena suatu galat tak terduga, Linux akan secara otomatis menyalakan kembali aplikasi dalam waktu 3 detik tanpa perlu Anda bangun tengah malam untuk menyalakannya!
  • NoNewPrivileges=true: Mencegah siapapun menggunakan aplikasi Anda untuk mencuri hak akses administrator tertinggi (Root) di server Linux Anda.

3 Perintah Linux untuk Menyalakan Layanan:

# 1. Beritahu Linux ada layanan baru terdaftar
sudo systemctl daemon-reload

# 2. Perintahkan Linux agar menyalakan website otomatis setiap kali server menyala (Auto-boot)
sudo systemctl enable widyaweb

# 3. Nyalakan website sekarang juga!
sudo systemctl start widyaweb

14.3 Mengunci Gembok Hijau (Domain Nama & Sertifikat SSL/HTTPS Gratis)

Pernahkah Anda membuka sebuah website lalu peramban Google Chrome menampilkan peringatan menakutkan berwarna merah bertuliskan: "Koneksi Anda Tidak Privat / Not Secure"? Itu terjadi karena website tersebut masih menggunakan HTTP biasa yang belum memiliki sertifikat enkripsi SSL.

Di server produksi, kita memasang perantara lalu lintas ringan bernama Nginx Reverse Proxy yang dikombinasikan dengan sertifikat digital gembok hijau resmi dari Let's Encrypt (Certbot) yang 100% gratis selamanya: 

# Memasang sertifikat gembok hijau HTTPS gratis hanya dengan satu perintah:
sudo certbot --nginx -d tokosaya.id -d www.tokosaya.id

Setelah perintah di atas selesai dijalankan, alamat website Anda otomatis berubah menjadi https://tokosaya.id dengan ikon gembok terkunci rapi di bilah peramban pengunjung. Semua data transaksi aman terlindungi dari penyadapan Wi-Fi publik!

14.4 Kepatuhan Hukum Terhadap UU Pelindungan Data Pribadi (UU PDP No. 27/2022)

Di Indonesia, keselamatan data pengguna bukan lagi sekadar himbauan moral, melainkan telah menjadi Kewajiban Hukum Negara yang diatur di dalam Undang-Undang Nomor 27 Tahun 2022 tentang Pelindungan Data Pribadi (UU PDP). Pelanggaran terhadap keamanan data dapat dikenakan sanksi denda administratif hingga puluhan miliar rupiah serta ancaman pidana kurungan.

🛡️ 4 Pilar Keamanan WidyaWeb Sesuai Mandat UU PDP
  1. Enkripsi Data Sensitif Saat Disimpan (Encryption At-Rest): Data pribadi seperti Nomor Induk Kependudukan (NIK), nomor telepon seluler, dan nomor rekening perbankan tidak boleh disimpan dalam teks mentah. WidyaWeb menyediakan enkripsi AES-256 bawaan sebelum data ditulis ke dalam basis data SQLite.
  2. Pembersihan Jejak Sensitif pada Berkas Log (Log Masking): Mesin pencatat CCTV (Logger) WidyaWeb secara otomatis mengenali dan menyamarkan kata kunci rahasia seperti kata sandi, token otentikasi, dan CVV kartu kredit sehingga berkas log server tetap bersih dan tidak membocorkan privasi pengguna.
  3. Hak untuk Dihapus (Right to Erasure / Account Deletion): Sesuai Pasal 8 UU PDP, setiap pemilik data berhak meminta akun dan data pribadi mereka dihapus secara permanen dari sistem Anda. Di WidyaWeb, Anda dapat mengimplementasikan rute penghapusan akun yang menghapus seluruh data terkait secara tuntas.
  4. Audit Trail Kriptografis yang Tidak Dapat Dimanipulasi: Setiap kali ada petugas admin yang membuka atau mengubah data pengguna, sistem mencatat waktu kejadian, alamat IP pengakses, dan identitas pengubah ke dalam tabel jejak audit (audit log) yang terikat stempel waktu kriptografis.

Lampiran A: Kamus Istilah Web untuk Pemula (Glosarium A sampai Z)

CRUD (Create, Read, Update, Delete) Empat operasi dasar dalam pengelolaan data: Membuat data baru, Membaca/melihat data, Mengubah data lama, dan Menghapus data.

HTTPS (HTTP Secure) Versi aman dari protokol HTTP yang dilengkapi enkripsi gembok SSL/TLS sehingga isi kiriman data tidak bisa diintip atau disadap orang lain.
JSON (JavaScript Object Notation) Format tulisan teks terstruktur yang sangat populer di seluruh dunia untuk mengirim data antar program komputer, menggunakan tanda kurung kurawal {} dan siku [].

Payload / Body Isi paket barang atau data formulir sebenarnya yang dikirimkan di dalam sebuah permintaan atau balasan HTTP.

RBAC (Role-Based Access Control) Sistem pembagian hak akses berdasarkan jabatan atau peran pengguna (misal: Admin boleh membuka semua halaman, Kasir hanya boleh membuka mesin kasir).
REST API Gaya arsitektur pembuatan API yang memanfaatkan metode standar web HTTP (GET, POST, PUT, DELETE) secara konsisten dan teratur.
Routing (Router) Sistem penunjuk jalan yang mengarahkan pengunjung ke fungsi yang tepat sesuai dengan alamat URL yang mereka ketikkan di peramban.

Status Code (Kode Status HTTP) Angka 3 digit balasan server yang memberi tahu apa yang terjadi: 200 (Sukses), 201 (Data Berhasil Dibuat), 400 (Permintaan Rusak), 401 (Belum Login), 403 (Dilarang Masuk), 404 (Halaman Hilang), 422 (Formulir Salah Isi), 500 (Server Mengalami Galat).
VPS (Virtual Private Server) Komputer virtual di pusat data (data center) yang menyala 24 jam dengan koneksi internet kencang dan IP publik, disewa untuk menaruh website agar bisa diakses seluruh dunia.

Lampiran C: Panduan Mengatasi 15 Pesan Galat yang Sering Ditemui Pemula

Ketika belajar koding, melihat pesan galat (Error Message) berwarna merah di layar monitor adalah hal yang sepenuhnya wajar dan dialami oleh setiap programmer di seluruh dunia. Jangan panik! Pesan galat sebenarnya adalah petunjuk ramah dari komputer yang memberi tahu bagian mana yang perlu diperbaiki.

No Pesan Galat yang Muncul Penyebab Paling Sering Solusi Langkah-demi-Langkah
1 Alamat port 8080 sudah digunakan oleh aplikasi lain Server Widya sebelumnya masih menyala di latar belakang, atau ada aplikasi lain (seperti XAMPP / Tomcat) yang memakai port 8080. Tutup terminal server sebelumnya, atau buka config.base.wya dan ganti nomor port menjadi 8081 atau 9090.
2 no such table: produk Tabel produk belum dibuat di basis data SQLite Anda. Jalankan perintah migrasi di terminal: widya craft.wya migrasi:jalankan.
3 Karakter tidak dikenal: '﻿' Berkas kode disimpan dengan format UTF-8 with BOM oleh teks editor bawaan Windows Notepad / PowerShell lama. Buka berkas di VS Code, lihat pojok kanan bawah, ubah UTF-8 with BOM menjadi UTF-8 biasa, lalu simpan ulang (Ctrl+S).
4 Variabel tidak terdefinisi: 'x' Anda menggunakan variabel x sebelum mendeklarasikannya dengan kata kunci misal, atau salah ketik huruf besar/kecil. Pastikan Anda menulis misal x = ...; terlebih dahulu sebelum variabel itu dipanggil. Periksa ejaan hurufnya.
5 JSON tidak valid pada request body Pengunjung atau aplikasi luar mengirim teks paket data yang rusak (misalnya lupa tanda petik dua atau koma salah letak). Pastikan format data yang dikirim adalah JSON standar yang valid dengan tanda petik dua di setiap kunci (key).
6 Akses ditolak: 403 Forbidden Pengguna sudah login, tetapi perannya tidak memenuhi syarat (misal: kasir biasa mencoba membuka menu rahasia admin). Pastikan akun yang digunakan untuk login memiliki peran (role) yang sesuai dengan aturan middleware di rute tersebut.
7 401 Unauthorized Pengunjung mencoba memanggil endpoint yang mewajibkan login tanpa menyertakan tiket sesi (cookie) yang sah. Lakukan login terlebih dahulu melalui endpoint /login untuk mendapatkan tiket sesi yang valid.
8 404 Not Found pada browser Alamat URL yang diketikkan di browser salah ketik atau belum didaftarkan di dalam fungsi router. Periksa kembali rute yang Anda buat di routes/api.wya. Pastikan alamatnya sama persis (misal: /api/produk).
9 Galat sintaks: kekurangan tanda '}' Ada blok kode fungsi atau kurung kurawal pembuka { yang lupa ditutup dengan pasangannya }. Periksa baris kode terakhir yang Anda edit di VS Code. Ikuti garis pemandu lekukan kode untuk mencari kurung kurawal yang belum tertutup.
10 database is locked Ada proses lain (seperti aplikasi SQLite Browser luar) yang sedang mengunci berkas storage/database.sqlite. Tutup aplikasi SQLite Browser pihak ketiga atau pastikan setiap transaksi database ditutup dengan commit/rollback.
11 422 Unprocessable Entity Data formulir yang Anda kirimkan melanggar aturan validasi skema (misal: panjang NIK kurang dari 16 digit). Lihat array rincian_kesalahan pada balasan JSON untuk melihat kolom formulir mana yang salah isi.
12 Berkas views/layout.html tidak ditemukan Folder views/ belum dibuat atau nama berkas salah ketik di dalam fungsi view engine. Pastikan struktur folder proyek Anda memiliki direktori views/ yang berisi layout.html.
13 Koneksi SSE terputus setelah 60 detik Proxy server Nginx di server VPS memutuskan sambungan karena menganggap koneksi sedang menganggur (idle timeout). Tambahkan baris proxy_read_timeout 3600s; pada berkas konfigurasi Nginx Anda untuk saluran SSE.
14 systemd: widyaweb.service failed Jalur berkas executable di ExecStart salah atau pengguna (user) tidak memiliki izin membaca folder aplikasi. Periksa log rincian galat Linux dengan mengetikkan perintah: journalctl -u widyaweb.service -e.
15 Ollama connection refused Layanan aplikasi Ollama lokal belum menyala di komputer Anda saat VS Code memanggil AI WidyaCoder. Buka aplikasi Ollama di komputer Anda atau ketikkan perintah ollama serve di terminal baru.
